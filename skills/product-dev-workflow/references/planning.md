# MVP-first planning

Read [the template](../assets/templates/implementation-plan.md). Inspect all prerequisite contents, source revisions, and unresolved decisions.

Choose the smallest set of complete journeys delivering useful value to intended users and validating the core product. Include essential security, integrity, deployment, observability, recovery, and documentation. Infrastructure alone or unfinished feature fragments are not a delivered MVP. Record included REQ/JRN IDs, exclusions, deferral rationale, release criteria, and usefulness measures. Honor confirmed business constraints and explain scope tradeoffs.

Make Phase 1 the MVP delivery phase. Choose later phases by value and dependencies; phase count is unrestricted and a scale phase is optional. Give each phase complementary delivered value and exit criteria. Account for every requirement through a phase, explicit deferral, or retirement.

Every TASK includes title, bounded description, source IDs, dependencies, useful subtasks, Definition of Ready, Definition of Done, measurable expected results, and affected documentation. Write tasks so a coding agent can execute them autonomously inside the approved product scope: identify authoritative inputs; state constraints and permitted implementation choices; name observable outputs and evidence; link BDD scenario IDs to automate; give validation commands when known or a project-grounded discovery rule when unknown; and define when to stop and report a blocker. Do not leave routine implementation decisions as vague “decide during implementation” notes. Give the agent selection criteria and authority to make reversible choices, while routing product, scope, security, compatibility, cost, and irreversible choices to the user. DoR identifies required inputs/decisions. DoD identifies completion evidence, appropriate verification, affected documentation, and deployment when applicable. Avoid arbitrary coverage targets and generic checklists.

Order dependencies without cycles. Split oversized tasks. Keep blocked work visible and draft. Estimate effort/dates only with explicit capacity assumptions; do not assert unsupported commitments. Include maintenance of the four mandatory files at actual/planned project boundaries and applicable Diátaxis docs in tasks and DoD. For `AGENTS.md`, require the concise product-workflow guidance described in [shared documentation rules](documentation-and-repo-rules.md); update it only when its paths, boundaries, commands, or durable instructions change.

Completion: Phase 1 delivers a complete useful outcome; full scope is accounted for; every task has required fields and is actionable by a coding agent without an implicit user decision; dependencies are coherent; each task names applicable BDD IDs and required validation evidence; no thread remains open without an explicit user-authorized TBD disposition; blockers, exact source revisions, workflow state, and documentation navigation are current. Once the plan is ready, recommend `/mvp` as the implementation step. Do not begin implementation as part of planning unless the user also requested it.
